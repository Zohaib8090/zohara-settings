# Settings: control over what apps may do (2026-10-13)

Owner's request: "full-fledged control to destroy, sandbox, or give some applications some things access", for example a
game installed from Flathub that does not use the dedicated graphics card. Most of the Flatpak part already existed
(`pages/app_details.rs`, `backend/app_details.rs`: network, files level, sound, graphics acceleration, all devices, Bluetooth,
camera, microphone, notifications, saved data, reset, uninstall; and the per-row dedicated-graphics button in `pages/apps.rs`).
The owner chose four gaps to build. Three are done, tested and pushed to alpha (not promoted to stable). The fourth is parked.

## 1. AUR and AppImage apps in Settings > Apps, graphics choice in the details (done, alpha)

* `backend/community_apps.rs`: `pacman -Qmq` (foreign packages) marks an app as **AUR** (`zohara-*` excluded: Zohara's own
  CI builds), and the Store's AppImages are found by their launchers (`X-Zohara-AppImage=<id>` in `~/.local/share/applications`,
  file in `~/.local/share/zohara-store/appimages`). Removal of an AppImage deletes the file, `.meta`, icon and launcher.
* `pages/apps.rs`: new sources `Aur` and `AppImage` (labels "AUR · pkg version" and "AppImage"); AUR apps uninstall like
  packages; an AppImage asks and removes its files (no password).
* `pages/app_details.rs`: new kinds `Aur` and `AppImage`; a **Graphics** group on a laptop with two chips: "Always use the
  dedicated graphics card" and "Open it now on the dedicated card" (same storage as the row button: the launcher key
  `PrefersNonDefaultGPU` for ordinary apps, a Flatpak override for Flatpaks).
* On the owner's laptop the dedicated-graphics path is *available*: NVIDIA RTX 3050 driver 615.71.09 and the matching
  Flatpak runtime `org.freedesktop.Platform.GL.nvidia-615-71-09` are installed, so a Flatpak game can use it.
* Clicked through (isolated data folder, `pacman -Qmq` shimmed to call `ark` an AUR app): the label, an AppImage row and its
  details, the graphics switch writing and removing `PrefersNonDefaultGPU=true`, the AppImage removal dialog and its files gone.

## 4. Restricted mode for apps that are not Flatpaks (NOT in main: branch `restricted-mode-wip`, local only)

Idea: bubblewrap (`/usr/bin/bwrap`, already installed because Flatpak needs it) around the app, with choices per app:
internet, sound, camera, USB devices, how much of the home folder (hidden / read only / all), folders.

* `backend/sandbox.rs`: the saved choices (`~/.config/zohara/sandbox/<launcher>.json`), the launcher rewrite (a copy in
  `~/.local/share/applications` whose every `Exec` is `zohara-settings --sandbox-run <launcher> -- <original>`, field codes kept,
  `DBusActivatable` switched off and restored, reversible, the system launcher never touched), `build_args` (the bubblewrap
  options, tested without touching the machine) and `run` (the `--sandbox-run` entry point in `main.rs`).
  `pages/app_sandbox.rs`: the switch and the choices in the details of every non-Flatpak app.
* Verified: 7 unit tests; a real bubblewrap test (`sandbox::tests::live_...`, ignored) with a marker file in the real home:
  hidden by default, `/usr` read only, the app's own settings folder writable and visible outside, an extra folder read only,
  with the internet off `/proc/net/dev` shows only `lo`, no camera nodes, **no disks even with USB devices allowed**, and
  the "everything" and "read only" home modes. In the Settings window: turning it on for Kate wrote the wrapped launcher and
  the profile, and the choices (internet, sound, camera, USB, files, folders) show and save.
* **Not working yet:** starting Kate from the sandboxed launcher (`gtk-launch org.kde.kate`) printed only the Settings log line
  and no Kate window or process was left. Likely cause (not verified): with `--unshare-pid` the first process in the sandbox is
  the app's init; Kate starts a background process and the first one exits, which ends the whole sandbox. Candidate fixes:
  run the command under a tiny init that waits for every child (`sh -c 'cmd; wait'` does not cover grandchildren; a reaper
  such as `tini` or a small Rust loop over `/proc` does), or drop `--unshare-pid` and accept that the app sees other
  processes. Test by running `bwrap` by hand with `kate -b`, then `kate -b --foreground`-style options. Also check the exact stderr
  (the launcher ran from `gtk-launch` with output in a file; only the Settings log line was there, so bubblewrap itself may have
  exited quietly).
* To resume: `git checkout restricted-mode-wip`. The UI says "experimental"; do not merge to main until Kate (a KDE app), a
  Qt app, an Electron app and an AppImage start and stay open, and an app started from a terminal is shown as not restricted.

## Swap after install (Power & battery > Swap) and a memory budget for AUR builds

Why: a computer installed with "No swap" (the owner's dad's 16 GB laptop) could never get swap later, and building PhotoCraft from the AUR (a Rust image editor, thin LTO, one codegen unit, full debug info, one job per core) used 9-10 GB, so the system stopped the Store's whole memory group.

### Settings: `src/backend/swap.rs`, `src/pages/swap_group.rs` (on alpha)

* **In use now:** memory, and each swap in `/proc/swaps` told apart (partition, swap file, compressed memory).
* **Compressed memory (zram) switch:** installs `zram-generator` (`pacman -S --needed`), writes `/etc/systemd/zram-generator.conf.d/zohara.conf` (`zram-size = min(ram / 2, 8192)`, zstd, priority 100), turns zswap off (the two together compress twice) and starts `systemd-zram-setup@zram0`. Off removes the file and turns zswap back on.
* **Swap file:** sizes 1/2/4/8/16 GiB plus "as much as memory (needed for Hibernate)", only those that leave 5 GiB free; create, replace and remove, each with a confirmation. On Btrfs the file lives in its own subvolume `@swap` mounted at `/swap` (fstab line added), made with `btrfs filesystem mkswapfile`; elsewhere a plain `/swapfile`. Priority 10.
* **Why a separate subvolume:** Btrfs refuses to snapshot a subvolume that holds a swap file in use, and Zohara snapshots `@` before every update. Proven: with the file inside `@` the snapshot fails with "Text file busy"; with `@swap` the snapshot of `@` works.
* **Hibernate row:** status only (Ready / Not set up / Not available, with the reason). One-click setup (the `resume=` and `resume_offset` boot options and an initramfs rebuild) is **not built**: it can stop the computer booting, so it needs a VM test first.
* Each change is one script run with `pkexec sh -c`, built from fixed text and a number (`file_create_script(gib)` clamps it). Exit codes: 3 swap file already there, 4 contents do not fit in free memory (nothing deleted), 5 not enough free disk space.

**Tested:** unit tests (8 for swap; whole suite 305 pass); `sh -n` on every script; the real create, second-create refusal, remove and no-room scripts were run against a real Btrfs filesystem (loop image with `@`, `@home`, `@snapshots`, in a privileged container, chroot) and left it clean; the zram config is accepted by the real `zram-generator` and a broken one is rejected; the page was opened in the app and the size dialog and Cancel were clicked (Cancel puts the row back).
**Not tested:** zram started for real, a swap file created on a real installed Zohara through the password prompt, and `ext4`/`xfs` (plain `/swapfile`) beyond syntax.

### Store: build budget for AUR installs (`zohara/zohara-store-rs/src/buildbudget.rs`)

* Budget = half of memory, never more than free memory minus 1 GB, at least 1 GB, at most 3/4 (4 GB computer: 2 GB; 8: 4; 16: 8; 32: 16; 128: 64). Jobs = budget / 1.5 GB, at most the cores.
* The build runs as `systemd-run --user --scope -p MemoryMax=<budget> -p CPUWeight=50 -- nice -n 10 yay ...` with `MAKEFLAGS`, `CARGO_BUILD_JOBS`, `NINJAFLAGS`, `CMAKE_BUILD_PARALLEL_LEVEL`. Only a hard limit is used: a soft limit (`MemoryHigh`) made a test hang while the kernel pushed the group into swap.
* The confirmation shows the budget for packages that are compiled (names not ending in `-bin`); an out-of-memory failure gets its own plain message (and mentions swap when there is none); the error text kept while installing is capped.
