# Settings features added 2026-10-09: how they work and where the code is

Companion to `zohara/docs/HANDOFF-2026-10-09.md` (state, channels, what is not verified). Each section: what it does, the mechanism, the files, the tests.
Backend modules hold the logic and its unit tests; `pages/` holds the screens.

## Equalizer (Settings > Sound > Equalizer)
* **Mechanism.** `backend/equalizer.rs` writes `~/.config/zohara/equalizer/filter-chain.conf` and runs `pipewire -c <that>` as the user service
  `zohara-equalizer.service` (`data/`, installed to `/usr/lib/systemd/user`; Settings enables it with `systemctl --user enable --now`). The config is
  PipeWire's filter chain with **built-in biquads** (no plug-ins): `pre` (linear gain) -> `eq1..eq10` (`bq_peaking`) -> `bass` (`bq_lowshelf` 120 Hz)
  -> `treble` (`bq_highshelf` 7 kHz). It provides a virtual output `zohara_eq`; while on, `zohara_eq` is the default output and its playback stream
  (`zohara_eq_out`) is aimed at the real device (`target.object`). `zohara-settings --eq-activate` / `--eq-deactivate` (service `ExecStartPost` /
  `ExecStopPost`) make it the default and give the real device back.
* **Live changes**: `pw-cli set-param <node> Props '{ params = [ "eq6:Gain" 3.0000 ... ] }'` (floats need a decimal point). `LiveApplier` is a thread that
  sends only the newest settings, 30 ms apart. Node id from `pw-dump` (`node.name == zohara_eq`).
* `pactl load-module libpipewire-module-filter-chain` does **not** work here ("No such entity"); and `pipewire -c` needs an **absolute** path and the
  `protocol-native`, `client-node`, `adapter` modules in the config or it fails with "can't connect".
* **Output picker interplay** (`pages/sound.rs`): the equalizer sink is hidden from the device lists; with the equalizer on, choosing a device calls
  `equalizer::retarget` (moves the `zohara_eq_out` stream) instead of `set-default-sink`. Volume/mute act on the default sink (the equalizer), like the tray.
  The equalizer's own stream is hidden from the mixer; apps on the equalizer are shown on its target device.
* State: `~/.config/zohara/equalizer.json` (enabled, target, preset, settings, own presets). Automatic headroom lowers the preamp by the biggest boost.
  The graph (`pages/equalizer.rs`) draws the shape without the preamp. RBJ biquad math (`response_db`) agrees with the real filter to 0.05 dB.
* Tests: 11 logic tests; `live_equalizer_shapes_the_sound_changes_live_and_moves_to_another_output` (silent HDMI outputs, tone + `parecord`).

## Sound mixer
* Boost: `plasmaparc` `[General] RaiseMaximumVolume` (written with `--notify`), sliders go to 150% (`BOOST_MAX`).
* **Rows outside a `ListBox` ignore clicks.** Rows redrawn after the page is built (`refresh_apps`, `refresh_mic_apps`) go in a fresh `ListBox`.
  `adopt_orphan_rows` only runs once, on the freshly built page.
* Per-app pickers resolve the app's streams **when you pick** (`move_app`): players such as Spotify open a new stream per track, so a stored stream
  index is stale. The server remembers the choice per app (WirePlumber), so later streams follow. The mixer does not redraw while a popover is open
  (`popover_open`).
* Long names: `marquee_factory` (list pop-up, slides while the pointer rests), `use_subtitle` (the chosen name shown in full).

## Recommended programs (Zohara Update)
* `data/recommended.json` -> `/usr/share/zohara/recommended.json`. Items: `package`, `title`, `why`, optional `when` (`intel-gpu`, `amd-gpu`,
  `nvidia-gpu`, `hybrid-gpu`; an unknown value is not offered) and `enable` (a service to turn on). Adding a program = edit the file and push (alpha).
* `sysupdate/recommended.rs`: offers items that are not installed and fit the hardware; unticked ones are remembered in
  `~/.config/zohara/recommended.json` (skipped, "Offer again" in the page). Only packages from the shipped list can be installed; refused while system
  updates are pending (same rule as Zohara packages); one `pkexec` for `pacman -Sy && pacman -S --needed` + `systemctl enable --now`.
* Hardware comes from `backend/gpu.rs` (`/sys/class/drm/card*/device/vendor`).

## Graphics choice per app (Settings > Apps > installed apps, laptops with two chips)
* `backend/gpu_pref.rs`. Ordinary app: a copy of its launcher in `~/.local/share/applications` with `PrefersNonDefaultGPU=true` and our marker
  `X-Zohara-GpuOverride=true` (turning it off deletes our copy); KDE then starts it with switcheroo's settings (verified with `kioclient exec`). Flatpak app:
  the settings go in its own environment: `~/.local/share/flatpak/overrides/<id>` `[Environment]` (edited directly; `--unset-env` only blanks) and
  `flatpak run --env=...` for "open now". Settings come from `switcherooctl list` (the `Discrete: yes` device).
* The NVIDIA part for Flatpak (`org.freedesktop.Platform.GL.nvidia-<driver>`) must be installed or a Flatpak app silently stays on the other chip
  (`flatpak_gpu_ready`, shown as a note).

## App details (click an app in Settings > Apps)
* `backend/app_details.rs` (logic) and `pages/app_details.rs` (screen).
* **Flatpak**: permissions = the app's own `[Context]` (`flatpak info --show-permissions`) with the person's overrides on top (`!x` removes);
  changed with `flatpak override --user --share/--socket/--device/--allow/--filesystem`; camera, microphone, notifications through the permission store
  (`flatpak permissions`, `permission-set`). Data in `~/.var/app/<id>`; Clear cache = its `cache/`, Clear data = everything in it. Both refuse while
  `flatpak ps` lists the app.
* **Ordinary apps**: folders are found from `pacman -Ql <pkg>`: programs in `/usr/bin` and folders directly under `/usr/share` **named like the app**, then
  looked up as `~/.config|.local/share|.local/state|.cache/<name>` and `<name>rc`/`<name>staterc` in `~/.config`. A block list (`SHARED_NAMES`: git, ssh,
  fontconfig, pipewire...) is never offered. Clear data = **`gio trash`** of the ticked folders (each must sit directly inside one of the four base
  folders; `allowed_for_trash`). Clear cache deletes `~/.cache/<name>`. "Running" = process name **or any open file inside the folders** (`in_use`):
  Chrome's process is called `chrome`, so the name alone misses it.
* Notifications: `plasmanotifyrc [Applications][<launcher id>] ShowPopups` (written with `--notify`) and, for Flatpak, the portal permission.
* Tests: 14 logic tests; `live_app_details_flatpak_permissions_take_effect_inside_the_sandbox` (Spotify, never started, overrides file restored),
  `live_native_folders_found_from_real_packages` (prints what would be offered), `live_trash_moves_an_app_folder_to_the_real_trash_and_it_can_be_put_back`.

## Plasma settings that need telling (accessibility, DND, shortcuts)
A changed config file is **not enough**: write with `kwriteconfig6 --notify` (`kconfig::write_notify`/`delete_notify`), and for the cursor also send
`dbus-send --type=signal /KGlobalSettings org.kde.KGlobalSettings.notifyChange int32:5 int32:0` (`kconfig::notify_cursor_changed`).
`plasma-apply-cursortheme --size` ignores the size when the theme is unchanged. Do-not-disturb's `Until` is Qt's `Y,M,D,h,m,s.ms`, local time.
High contrast is `data/color-schemes/ZoharaHighContrast.colors` (installed to `/usr/share/color-schemes`).

## Live tests (`cargo test <name> -- --ignored --nocapture`)
`live_equalizer_*`, `live_accessibility_*`, `live_dnd_*`, `live_custom_shortcut_*`, `live_gpu_choice_*`, `live_flatpak_gpu_*`, `live_app_details_*`,
`live_native_folders_*`, `live_trash_*`, plus `offer_here` (what Zohara Update would offer here), `detect_here` (GPU vendors). They change the real
session briefly and put everything back. **Never run them while the owner is in a call**: the equalizer test records from HDMI monitors, the DND test
toggles do-not-disturb.
