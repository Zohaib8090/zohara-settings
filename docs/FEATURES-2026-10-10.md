# Settings features added 2026-10-09 to 10: how they work and where the code is

Companion to `zohara/docs/HANDOFF-2026-10-10.md` (state, channels, what is not verified) and `FEATURES-2026-10-09.md` (the earlier ones). Backend
modules in `src/backend/` hold the logic and its tests; `src/pages/` holds the screens. Live tests are `#[ignore]`d: `cargo test live_ -- --ignored --nocapture`
(they change the real session briefly and put it back; not while the owner is in a call).

## Personalization (`pages/personalization.rs`)
* **Taskbar** (`backend/desktop_style.rs`): hide (always / auto / when a window covers it), floating, background (automatic / solid / see-through), size. Set
  through Plasma's scripting (`p.hiding`, `p.floating`, `p.opacity`, `p.height`) on the panel that holds the task manager. State is read from the **running
  shell** (a script via `gdbus call`), because `plasmashellrc` is written seconds late.
* **Window buttons**: close/minimize/maximize left or right: kwinrc `[org.kde.kdecoration2] ButtonsOnLeft/Right`, then `KWin.reconfigure`. An empty list is a
  real value (`kreadconfig6 --default` sentinel), not "unset".
* **Desktop effects** (`backend/effects.rs`): on/off through kwinrc `[Plugins] <id>Enabled` plus KWin's `loadEffect/unloadEffect`; `isEffectLoaded` is the truth.
  Jelly strength (kwinrc `[Effect-wobblywindows]`), minimize style and open/close style (one effect each, the others turned off).
* **Quick looks** (`backend/looks.rs`): four presets made of the options above; `capture()` / `apply()` so a look can be undone.
* **Desktop cube** (`backend/cube.rs`, rows in `cube_rows()`): see the cube section below.
* **Desktops** (`backend/desktops.rs`, `desktop_rows()`): number of desktops (D-Bus `org.kde.KWin.VirtualDesktopManager` `createDesktop/removeDesktop`, changed
  at the end) and **Dynamic desktops** (below).
* **Live wallpaper** (`backend/live_wallpaper.rs`, `live_wallpaper_rows()`): see below.

## Zohara Cube (QML KWin effect)
* Files: `data/cube-effect/` (`metadata.json`, `contents/config/main.xml`, `contents/ui/{main,ScreenView,DesktopView,WindowTray}.qml`), installed to
  `/usr/share/kwin/effects/zoharacube` by `PKGBUILD` (depends `qt6-quick3d`). Development home and README: `~/Documents/zohara-cube` (local repo).
* Options in kwinrc `[Effect-zoharacube]` (read by the effect as `effect.configuration`): `Duration`, `OpenCube`, `Pullback`, `Tilt`, `OverviewGesture`.
  `backend/cube.rs` reads/writes them and runs `plan(on, overview_gesture)`: turning the cube on turns **Slide** off (and KWin's **Overview** off when the cube
  owns 4 fingers up); off puts them back.
* Behaviour: 3 and 4 finger left/right turn the cube and **follow the fingers** (QML `SwipeGestureHandler`, `progress` 0..1; KWin itself picks the
  desktop on release, the effect settles on `Workspace.currentDesktop`). 4 fingers up / `Meta+C` opens the overview: the half-circle of faces closes into a
  prism, the camera pulls back, the wallpaper (`DesktopBackground`) sits behind, a mouse drag turns it any number of laps, release snaps to a face.
* **Overview layer** (`WindowTray.qml`, always shown with the overview): desktop chips along the top (tap = pick; **double tap = menu** with move left /
  right / first and delete; a `⋯` on the picked chip does the same), "+ New desktop" (tap = empty desktop; drop or armed window = a desktop with it); the
  window tray along the bottom (windows of the picked desktop; the app icon on a card shows every window of that app on all desktops; a card is dragged
  onto a chip, or armed with **Move** and then a chip is tapped, for touchpads; tap a card = go to that window). Bar and tray glide in with `effect.amount`
  (the zoom, 0..1, also driven by the fingers).
* **Reordering desktops** (`moveDesktop` in `main.qml`): KWin cannot reorder, so every window's `desktops` is re-assigned and the names are passed along
  with `setDesktopName` over D-Bus (`DBusCall`); you stay with the same windows. Tested only on a fake workspace (`zohara-cube/tests/move_desktop_test.js`).
* Safety: only `normalWindow && !dock && !desktopWindow && !dialog && !transient && !skipTaskbar` can be moved (the panel is never touched).
* Tests: `zohara-cube/tests/run.sh` (qmltestrunner with simulated mouse, 16 tests, the real `WindowTray.qml` with stand-in KWin types) and `run-js.sh`.
* Traps: `GOTCHA.md` "2026-10-10" (cache, `escape`, `layer`, `required property model`, logging).

## Live wallpaper
* Plugin `data/live-wallpaper/` (`Plasma/Wallpaper`, id `org.zohara.livewallpaper`, QtMultimedia `MediaPlayer` + `VideoOutput`, pauses when the desktop is
  not visible) installed to `/usr/share/plasma/wallpapers`; depends `qt6-multimedia`, `qt6-multimedia-ffmpeg`.
* Settings writes it with the scripting API on every desktop (`desktops().forEach(... wallpaperPlugin, writeConfig ...)`; the path is JS-escaped and
  tested). "Go back to a picture" sets `org.kde.image` again (its picture is still stored). State is read from the shell.

## Dynamic desktops (KWin script `data/dynamic-desktops/`)
* Installed to `/usr/share/kwin/scripts/zoharadynamicdesktops`; turned on with kwinrc `[Plugins] zoharadynamicdesktopsEnabled`, options in
  `[Script-zoharadynamicdesktops]`: `Mode` (`manual` default / `auto`), `GroupByApp`, `SwitchToNew`, `CloseEmpty`, `MaxDesktops`, `Ignore`, `SettleSeconds`.
  `desktops::write()` restarts the script (off, reconfigure, on) so it re-reads them.
* Manual: `registerUserActionsMenu` ("Move to a new desktop" in the title bar menu) and `registerShortcut` (`Meta+Shift+N`). Auto: `workspace.windowAdded`.
* Desktops it makes end with an invisible `U+200B` in the name; only those are removed, when their last window closes (a sweep also clears stray ones, not
  during `SettleSeconds` after login). **System helpers never get a desktop** (polkit password prompt, wallet, krunner, lock/login screens, portals...:
  the `SYSTEM` list in `main.js`): a prompt on a desktop of its own is a prompt nobody answers.
* Tests: `tests/run-dynamic-desktops-tests.sh` (fake workspace, both modes).

## Sound balance (`backend/balance.rs`, `balance_group()` in `pages/sound.rs`)
* One slider per output device with a left and a right side (devices with only `aux0..7` or mono are not listed). Balance = how much the quieter side is turned
  down; the **master volume (loudest channel) is kept**. The main Volume slider now goes through `set_default_output_volume` and **keeps the balance** (a plain
  `set-sink-volume 60%` made both sides equal). `Latest<T>` runs only the newest value while a slider is dragged.
* Real check: `live_balance_on_a_real_output_is_set_read_back_and_restored` (silent HDMI sink only).

## Smaller things
* **Lock screen**: `data/pam-kde` -> `/etc/pam.d/kde` (no `pam_faillock`; `backup=` so edits survive). Reason and evidence in the handoff.
* **Live refresh** `pages/live.rs`: `live::every(widget, secs, tick)`; used by the battery card, System memory/storage, Bluetooth devices (2 s, it rebuilds rows).
* **Privacy indicator** `backend/privacy_indicator.rs`: `plasma_script` falls back to the tray applet's own config; `tray_found()` makes "success" mean a tray was changed.
* **Memory & performance** (Power & battery, `backend/memory.rs`): `vm.swappiness`, `vm.vfs_cache_pressure`, zswap; written to `/etc/sysctl.d/99-zohara-memory.conf`
  and `/etc/tmpfiles.d/zohara-zswap.conf` by one `pkexec`; defaults write nothing. Swap file resizing was left out on purpose (btrfs).
* **Scroll direction** first row on every Mouse/Touchpad card (`pages/input_devices.rs`).
* **Taskbar launcher**: `zohara-settings.install` `fix_settings_launcher()` gives the pinned `systemsettings.desktop` our icon and `StartupWMClass=os.zohara.Settings`;
  the ISO script (`zohara/zohara-profile/.../customize_airootfs.sh`) does it for new installs.
* **CI**: `.github/workflows/build.yml` pulls the mirror image (see GOTCHA).

## Cube overview animation settings (added later on 2026-10-10)

The desktop bar and window tray in the cube overview glide in and out on their own timer (they used to follow the cube's zoom).
Settings → Personalization → Desktop effects: "Slide the desktop bar and window tray" (kwinrc `[Effect-zoharacube]` `TrayAnimation`, default on)
and "Slide time" (`TrayTime`, 100 to 1200 ms, default 350). Off = they appear at once. Like all cube QML changes this needs a log out and in
after the update. Tests: `zohara-cube/tests/run.sh` (17 tray tests).

The cube overview (Meta+C, 4 fingers up) now also opens with a single desktop, so "+ New desktop" is reachable; before it silently did nothing
when only one desktop existed.

Cube overview scroll: the mouse wheel (one notch = one desktop) and two-finger touchpad scrolling turn the whole cube in the overview
(`WheelHandler` in `ScreenView.qml`); a touchpad settles on the nearest desktop 160 ms after the fingers stop. Not yet tried by hand.
